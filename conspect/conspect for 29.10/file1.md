# Теория по паре за 29.10

*   **Что такое Dapper?** Это микро-ORM. Он не пишет SQL за вас и не отслеживает изменения объектов, а только выполняет ваш SQL и маппит результат в C#-объекты. В связке с PostgreSQL вы получаете скорость, близкую к чистому ADO.NET, плюс полный контроль над запросами.
*   **Драйвер БД:** Dapper не содержит драйверов БД. Работа с PostgreSQL целиком обеспечивается **Npgsql** - официальным ADO.NET-провайдером.
*   **Управление соединениями:** Никогда не храните `NpgsqlConnection` в `static` поле и не переиспользуйте один экземпляр между запросами. Пул соединений уже решает задачу переиспользования - достаточно создавать новый объект на каждый запрос. Dapper не открывает и не закрывает соединение сам, лучше управлять этим явно через `using`.
*   **Маппинг `snake_case`:** PostgreSQL приводит незакавыченные идентификаторы к нижнему регистру: `UserName` превращается в `user_name`. Dapper по умолчанию ищет точное совпадение имён, поэтому свойство `UserName` не заполнится из колонки `user_name`. Решение - включить `DefaultTypeMap.MatchNamesWithUnderscores = true`.
*   **Особенности PostgreSQL:**
    *   **`RETURNING`** - позволяет получить вставленную строку или ID в том же запросе, без второго обращения к БД.
    *   **`EXCLUDED`** - псевдотаблица с данными, которые пытались вставить (используется в `ON CONFLICT`).
    *   **Массивы и `ANY`** - правильный способ передать список в PostgreSQL - массив + `ANY`, а не генерация `IN (@p1, @p2)`. Npgsql сам превращает `int[]` → `integer[]`, `string[]` → `text[]`.
    *   **JSONB** - при передаче параметра как `text` обязательно приведение `@Payload::jsonb`.
    *   **Даты** - Npgsql 6+ строго различает `timestamp`/`timestamptz`. `DateTime` с `Kind=Utc` соответствует `timestamptz`, `DateOnly` маппится на `date`.
*   **Связи (Multi-mapping):** 
    *   Как работает `splitOn`: Dapper читает колонки по порядку. Всё до указанной колонки идёт в первый тип, начиная с неё - во второй. Порядок колонок в `SELECT` критичен.
    *   Dapper не собирает коллекции автоматически (один-ко-многим). Для этого нужна ручная группировка через `Dictionary`.
*   **Транзакции:** Обязательно передавайте `transaction: tx` в каждый вызов. Если забыть - операция выполнится вне транзакции, и откат её не затронет.
*   **Производительность:**
    *   `COPY` в разы быстрее `INSERT` для больших объёмов, но не поддерживает `ON CONFLICT` и `RETURNING`.
    *   `OFFSET` работает плохо на больших значениях (PostgreSQL всё равно читает и отбрасывает строки). Для больших таблиц используется keyset-пагинация по `id > @LastId`.
*   **Асинхронность:** Метод `Query`/`Execute` без `Async` блокирует поток на время сетевого round-trip. В ASP.NET Core это приводит к исчерпанию пула потоков под нагрузкой, поэтому всегда используются `*Async`-версии.

### Что было сделано по шагам
1. Развертывание и настройка
Поднял БД в Docker, настроил строку подключения и фабрику IDbConnectionFactory. Включил MatchNamesWithUnderscores = true для автоматического маппинга snake_case из БД в PascalCase C#.

2. Базовый CRUD и RETURNING
Реализовал базовые операции через QueryAsync и ExecuteAsync. Использовал преимущество PostgreSQL - оператор RETURNING для получения сгенерированных ID и вставленных строк за один запрос.

3. Работа с массивами и JSONB
Научился передавать массивы в SQL через ANY (вместо IN). Разобрался с JSONB: настроил чтение, запись с приведением ::jsonb и обновление ключей через оператор конкатенации ||.

4. Починка багов из конспекта
Столкнулся с ошибкой DateOnly в Dapper 2.1.35. Решил обновлением пакета до 2.1.44. Также исправил баг конспекта с splitOn: "id" в связях один-ко-многим, добавив уникальные алиасы (task_id) для корректной группировки задач.

5. Массовые операции
Сравнил скорость вставки 100 000 строк. Выяснил, что бинарный COPY (BeginBinaryImportAsync) работает в разы быстрее, чем обычный INSERT через unnest.

6. Пагинация и Транзакции
Сделал обычную пагинацию через OFFSET/LIMIT (через QueryMultiple). Освоил транзакции: обернул создание проекта и его первой задачи «Kickoff» в атомарную операцию с BeginTransactionAsync.
